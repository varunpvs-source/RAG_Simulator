Why do chunk size and overlap matter?

Very small chunks can lose context; very large chunks may include distracting information. Overlap helps preserve details that fall near chunk boundaries, but too much overlap creates duplicate content and increases index size.

3. Turn chunks into embeddings

An embedding represents meaning as a numerical vector.

NOT RUN

In a real RAG system, an embedding model maps each chunk to a high-dimensional vector. This offline simulator uses a tiny transparent word-feature vector so you can inspect the idea—it is not a real semantic embedding model.

Where are embeddings stored?

Often in a vector database or search index, alongside the original text and metadata (such as source, page, access permissions, or document title). At query time, the question is embedded using the same model and compared with stored vectors.

What can still go wrong?

Retrieval failure: the needed fact is not among the selected chunks. Context failure: the retrieved text is incomplete or contradictory. Generation failure: a real model may misread the context or add unsupported details. Production RAG should test retrieval and answer quality, cite sources, enforce permissions, and say when evidence is missing.
